\chapter{Background and State of the Art}
\label{chap:background}

This chapter surveys the technical background underlying the routing mechanism
developed in this dissertation. It begins with the challenges of multi-hop
wireless communication and the MANET paradigm, then describes the TDMA
medium-access strategy and the RA-TDMAs+ protocol that governs the network
used in this work. The TDMA implementation framework built by
Almeida~\cite{almeida2023synchronization} is presented next, as it served as
the direct foundation for the implementation. The chapter concludes with a
review of MANET routing approaches and an analysis of the previous routing
work by Morais~\cite{morais2024synchronization}.

\section{Multi-hop Wireless Communication}
\label{sec:wireless}

\subsection{The Shared Medium Problem}

Wireless communication differs fundamentally from wired communication because
all nodes within radio range share the same physical medium. Two simultaneous
transmissions on the same frequency and channel corrupt each other at any
receiver within range of both senders, a condition known as a collision.
Managing access to the shared medium without collisions is the role of the
Medium Access Control (MAC) protocol.

IEEE 802.11 (WiFi), the standard used in this work, employs Carrier Sense
Multiple Access with Collision Avoidance (CSMA/CA). A node wishing to
transmit first listens to the channel; if the channel is detected as idle,
the node waits a randomly chosen backoff interval and then transmits. The
random backoff reduces the probability that two nodes attempt to transmit
simultaneously, but it does not eliminate it: when two nodes independently
select the same backoff value, their transmissions collide.

A subtler problem arises from the limited range of wireless radios. Two nodes
that are each within range of a common third node may be out of range of each
other, so neither can detect the other's transmissions. When both transmit
simultaneously, the frames collide at the common node without either sender
being aware. This is the hidden terminal problem, and it cannot be fully
resolved by CSMA/CA alone. Under high traffic load, repeated collisions and
backoffs cause significant throughput degradation and unpredictable latency,
making CSMA/CA unsuitable as the sole MAC mechanism for real-time
applications.

\subsection{Ad-hoc and Mobile Ad-hoc Networks}

A wireless ad-hoc network is formed autonomously by the communicating devices
themselves, without relying on access points, base stations, or any
pre-existing infrastructure. Each device is simultaneously a communication
endpoint and a potential relay for traffic destined to other nodes. When two
nodes are not within direct radio range, packets can still reach their
destination by traversing one or more intermediate relay nodes, a mechanism
known as multi-hop forwarding.

A Mobile Ad-hoc Network (MANET) extends this concept to scenarios where nodes
move freely~\cite{conti2014mobile}. Node mobility causes the set of available
wireless links to change continuously: a link that exists at one moment may
disappear moments later as a node moves out of radio range, and new links
appear when nodes move into range of each other. Routing protocols must
therefore adapt continuously, detecting link failures and computing alternative
paths without any centralised coordinator.

MANETs impose additional constraints beyond those of static ad-hoc networks.
Nodes are typically battery-powered, so energy efficiency in protocol design
matters. The topology can change faster than routing protocol convergence
times, creating transient periods during which some destinations are
unreachable. Security and privacy are also concerns given the open nature of
the medium, although these fall outside the scope of the present work.

Despite these challenges, MANETs are the enabling technology for a wide range
of operational scenarios: emergency coordination after infrastructure
destruction, military tactical communications in contested environments, and
teams of autonomous robots that must remain in contact while navigating freely
through complex environments. The last scenario is the direct motivation for
this work.

\subsection{Network Layering}

The networking functions relevant to this dissertation are organised according
to the layered model shared by both the OSI reference model and the TCP/IP
architecture. The \textbf{Physical layer} converts bits into signals
appropriate for the transmission medium (radio waves in the case of WiFi).
The \textbf{Data Link layer} controls access to the shared medium through the
MAC sub-layer and groups bits into frames; IEEE 802.11 CSMA/CA and RA-TDMAs+
operate at this layer. The \textbf{Network layer} handles logical addressing
and packet forwarding across multiple hops; IP operates here, and it is at
this layer that the routing mechanism developed in this dissertation installs
forwarding decisions into the kernel. The \textbf{Transport layer} provides
end-to-end reliability and flow control (TCP) or lightweight datagram delivery
(UDP). \textbf{Application layer} protocols make use of the transport
services; in this work the application is a real-time video stream.

The distinction between Layer 2 (data link) and Layer 3 (network) forwarding
is central to understanding the difference between the previous routing
approach by Morais and the one developed here, as discussed in
Section~\ref{sec:related-work}.

\section{Time Division Multiple Access and RA-TDMAs+}
\label{sec:ra-tdma}

RA-TDMAs+~\cite{oliveira2018clockless} is a TDMA protocol designed for
dynamic ad-hoc mesh networks. It achieves clockless relative
synchronisation without requiring GPS or any external time reference,
reduces interference among team members, and runs as an overlay on top of
the underlying IEEE 802.11 CSMA/CA hardware, which continues to handle
external interference from nodes outside the team. The protocol is the
product of combining the synchronisation method of RA-TDMAs~\cite{sousa2012ra}
with the topology-tracking and membership-management mechanisms of
RA-TDMA+~\cite{oliveira2018clockless}, taking the most effective features
of each.

\subsection{TDMA}

Time Division Multiple Access (TDMA) is a channel-sharing protocol that
partitions time into a repeating sequence of rounds, each subdivided into
$N$ equal slots. Every node in the network is assigned one unique slot per
round and is permitted to transmit data only within that slot. Because
transmissions are scheduled rather than contended, two nodes can never
occupy the channel simultaneously, eliminating collisions by construction.

If $T_{slot}$ is the slot duration and $N$ the number of active nodes,
the round period $T$ is:

\begin{equation}
T = N \times T_{slot}
\label{eq:frame}
\end{equation}

Figure~\ref{fig:tdma-round} illustrates the round structure for a
network with $N$ nodes, where the slots are numbered sequentially and
the sequence repeats periodically.

\begin{figure}[h]
\centering
\includegraphics[width=0.78\textwidth]{fig_tdma_round}
\caption{TDMA round structure. Each node is assigned one numbered slot
per round; the round repeats with period $T$.}
\label{fig:tdma-round}
\end{figure}

A packet that arrives at the transmit queue must wait at most one full
round before it can be sent, giving a deterministic upper bound on
access latency. This property makes TDMA well suited to real-time
applications that require predictable timing, such as video streaming.

\subsection{RA-TDMA}

For a TDMA round to operate without slot overlaps, every participating
node must perceive slot boundaries in the same way. In infrastructure
networks, a base station broadcasts a reference clock that all devices
lock onto. In ad-hoc networks this centralised reference does not exist,
and a distributed synchronisation mechanism is needed instead.

RA-TDMA addresses this by having nodes synchronise through the timing
of each other's transmissions, without requiring any shared external
clock. Each node transmits a state packet at the beginning of its
designated slot. Receivers observe when those packets arrive and
compare the arrival time to the expected time, deriving a per-packet
delay estimate. These estimates are used to progressively adjust slot
boundaries so that overlaps are driven toward zero. The protocol can
be layered on top of any wireless communication technology.

Two versions of RA-TDMA are relevant to this work: RA-TDMAs~\cite{sousa2012ra},
which contributed the synchronisation algorithm, and
RA-TDMA+~\cite{oliveira2018clockless}, which contributed the
topology-tracking mechanism.

\subsection{RA-TDMAs: Synchronisation Algorithm}
\label{sec:ratdmas-sync}

RA-TDMAs~\cite{sousa2012ra} was originally developed to support video
streaming between Unmanned Aerial Vehicles (UAVs) and a ground base
station over a multi-hop line topology. In this setting each UAV relays
the video stream one hop closer to the base station, up to a maximum of
five hops; each additional hop introduces forwarding delay that
accumulates at the destination.

The synchronisation mechanism works as follows. The header of each
transmitted packet carries the slot ID and the transmission offset
$p_k$, defined as the time elapsed since the start of the sender's
slot at the moment the packet was sent. A receiving node $j$ observes
the real arrival time $rx_k$ of packet $k$ from node $i$ and computes
the synchronisation delay $\delta_k$ as the difference between the
observed arrival and the arrival that would have occurred if the two
nodes were already perfectly synchronised:

\begin{equation}
\delta_k = (rx_k - \hat{rx}_k + T/2)_T - T/2
\label{eq:delay}
\end{equation}

The modular arithmetic, denoted by the subscript $T$, wraps the result
into the interval $(-T/2,\; T/2)$, disambiguating whether the packet
arrived early or late relative to the expected slot.

To compute $\hat{rx}_k$, the receiver must first estimate where node
$i$'s slot begins. Given that node $j$ knows its own slot start
$B^{(j)}$ and that slots are of equal length $s = T/n$ and ordered by
node ID, the expected slot start of node $i$ as seen by node $j$ is:

\begin{equation}
\hat{B}^{(i)}_k = (B^{(j)} - (j - i)\,s + T)_T,
\quad j, i \in [1, n]
\label{eq:expected-slot}
\end{equation}

Adding the transmission offset $p_k$ yields the expected packet arrival:

\begin{equation}
\hat{rx}_k = (\hat{B}^{(i)}_k + p_k)_T
\label{eq:expected-rx}
\end{equation}

Substituting into Equation~\ref{eq:delay} gives the full expression
for $\delta_k$:

\begin{equation}
\delta_k = (rx_k - (\hat{B}^{(i)}_k + p_k) + T/2)_T - T/2
\label{eq:delay-full}
\end{equation}

Before a node starts transmitting at the beginning of its slot, all
packet delay estimates recorded during the previous round are analysed
and a delay function $f$ is used to determine the shift to apply. Three
methods are defined for this analysis:

\begin{description}
\item[Minimum delay] Uses the smallest observed $\delta_k$. The slot
  advances by the least amount, making conservative corrections. This
  reduces the risk of advancing the slot so far that it overlaps with
  the preceding slot, but it is the slowest to converge.
\item[Maximum delay] Uses the largest observed $\delta_k$. The slot
  advances aggressively, reducing the chance of overlapping with the
  following slot, at the cost of a higher risk of encroaching on the
  preceding one.
\item[Median delay] Uses the median of all $\delta_k$ values,
  dampening the influence of outliers caused by occasional retransmissions
  or interference spikes. This balances the trade-offs of the two
  extreme approaches and is the strategy adopted in RA-TDMAs+.
\end{description}

The selected delay value is bounded to prevent excessively large
corrections, and slots can only be shifted forward (delayed), never
backwards:

\begin{equation}
\Delta(r) = \min\!\Bigl(\max\!\bigl(f(\delta_1,\,\delta_2,\,\ldots),\;0\bigr),\;
\Delta_{max}\Bigr)
\label{eq:shift}
\end{equation}

where $\Delta_{max}$ is a configurable ceiling, typically 25\% of the
slot duration. The slot start for the next round is updated as:

\begin{equation}
B^{(j)}(r) = B^{(j)}(r-1) + \Delta(r)
\label{eq:slot-start}
\end{equation}

All nodes continuously apply this adjustment until no delay is detected,
at which point the round structure has converged and transmissions no
longer overlap.

\subsection{RA-TDMA+: Topology and Membership}
\label{sec:ratdma-plus}

RA-TDMA+~\cite{oliveira2018clockless} extended the RA-TDMA approach to
fully dynamic mesh networks where the set of communicating nodes is not
fixed and not all pairs of nodes have a direct radio link. Two key
mechanisms were introduced: a round structure that adapts dynamically
to team membership changes, and a topology dissemination protocol that
gives every node a globally consistent view of the network.

\subsubsection{Round Structure and Slot Assignment}

The set of nodes currently active in the team is denoted $\tau_A$, and
the number of active nodes is $N = |\tau_A|$. Both quantities change
dynamically as nodes join or leave. The round period $T_{up}$ is
chosen according to the real-time requirements of the application and
remains fixed. Each node receives exactly one slot of duration:

\begin{equation}
t_{slot} = \frac{T_{up}}{N}
\label{eq:slot-duration}
\end{equation}

This means that as the team grows, slot duration decreases
proportionally, allowing new members to be absorbed without changing
the total round period. Slots are assigned in ascending order of each
node's unique numeric ID: the node with the smallest ID in $\tau_A$
receives slot $s_0$, the next smallest $s_1$, and so on. For example,
if $\tau_A = \{\text{ID}_2, \text{ID}_3, \text{ID}_5\}$, then
$\text{ID}_2 \to s_0$, $\text{ID}_3 \to s_1$, and
$\text{ID}_5 \to s_2$~\cite{oliveira2018clockless}.

\subsubsection{State Dissemination: Flooding with Aggregation}

In a mesh network, not all nodes have a direct radio link to each
other. A node that is two or more hops away from another cannot
observe its transmissions directly. To overcome this, RA-TDMA+ uses a
flooding-with-aggregation mechanism.

At the start of each slot, the transmitting node broadcasts its current
state as a multicast message. This state includes its local view of
team membership, connectivity to neighbours, and an age variable for
each piece of information that tracks how recently it was updated.
Nodes that receive this broadcast merge the incoming state with their
own local state, always keeping the most recently timestamped entry for
each piece of data. At the start of their own slot, they rebroadcast
the merged state.

Through this process, information travels one hop per round. After a
number of rounds equal to the network diameter, every node has received
contributions from all others, achieving a globally consistent shared
state. The age variables prevent old data from overwriting more recent
updates as information circulates through the network.

Figure~\ref{fig:flooding} illustrates this process for a four-node
network in which node~4 joins via node~2. In round~1, node~4 broadcasts
its state to node~2, its only neighbour. In round~2, node~2 merges the
received state with its own and rebroadcasts, reaching nodes~1, 3, and~4.
After two rounds the entire network holds a consistent shared state.

\begin{figure}[h]
\centering
\includegraphics[width=0.90\textwidth]{fig_flooding}
\caption{Flooding with aggregation. In round~1 (left), node~4 broadcasts
its state to its sole neighbour, node~2. In round~2 (right), node~2
rebroadcasts the merged state to all its neighbours, completing

\label{fig:flooding}
\end{figure}

\subsubsection{Topology Tracking}

The network topology is represented as a connectivity matrix $M$ of
size $N \times N$. Each entry $M_{jk}$ is a binary value indicating
whether node $j$ is currently receiving transmissions from node $k$:

\begin{equation}
M_{jk} = \begin{cases}
1 & \text{if node } j \text{ receives from node } k \\
0 & \text{otherwise}
\end{cases}
\label{eq:matrix}
\end{equation}

Each node is solely responsible for maintaining its own row of $M$.
Before broadcasting, it updates row $j$ to reflect which neighbours
it has heard in the most recent rounds. When a matrix is received from
another node, only the rows for which the incoming age value is more
recent than the local copy are updated. This ensures that topology
changes propagate through the network within one round after they
occur, while stale information is never able to overwrite fresh data.

Figure~\ref{fig:connectivity} shows how the connectivity matrix evolves
when a new node joins the network. When node~2 joins and connects to
node~4, a new row and column are added to the matrix, and the updated
topology is reflected in the network graph.

\begin{figure}[h]
\centering
\includegraphics[width=0.82\textwidth]{connectivity}
\caption{Update of the connectivity matrix and network topology after
node~2 joins the network. The matrix gains a new row and column,
and the link between node~2 and node~4 becomes visible to all nodes.}
\label{fig:connectivity}
\end{figure}

\subsubsection{Membership Tracking}

Keeping an accurate record of which nodes belong to $\tau_A$ is
essential for correct slot allocation. Node additions and removals are
detected through the connectivity matrix:

\begin{itemize}
  \item \textbf{Node joins:} when a new node's row appears for the
    first time in a received matrix broadcast, the local copy is
    extended with a new row and column, $N$ is incremented, and the
    TDMA core is notified to reorganise the round. The updated layout
    propagates through the network in the following broadcast.

  \item \textbf{Node leaves:} when a node's row has not been refreshed
    for more than a threshold number of consecutive rounds (three rounds
    in the implementation used in this work), all nodes independently
    detect the departure, remove the corresponding row and column,
    decrement $N$, and contract the round accordingly.
\end{itemize}

Because every node applies the same deterministic rules to the same
shared state, all nodes converge to the same slot layout without
requiring any explicit coordination message.

\subsection{RA-TDMAs+: Combined Operation}

RA-TDMAs+ brings together the synchronisation algorithm of RA-TDMAs
(Section~\ref{sec:ratdmas-sync}) and the topology and membership
mechanisms of RA-TDMA+ (Section~\ref{sec:ratdma-plus}). The result
is a single protocol that provides collision-free medium access,
clockless distributed synchronisation, and a continuously updated
network topology view, all without any external reference or
centralised coordinator.

The two mechanisms interact through the spanning tree of the
connectivity matrix. The synchronisation algorithm requires each
node to observe delays from its neighbours, but in a mesh topology
with cycles, combining delays from multiple paths would create
synchronisation loops. RA-TDMAs+ resolves this by computing the
Minimum Spanning Tree of $M$ and filtering delay observations so
that only delays from links present in the spanning tree are used
in the computation of $\Delta(r)$.

In the three-node implementation used in this work, each slot has
a duration of 50\,ms with a guard interval of 5\,ms, giving 45\,ms
of usable transmission time per slot and a round period of 150\,ms,
as shown in Table~\ref{tab:frame}.

\section{TDMA Framework}
\label{sec:framework}

The TDMA framework developed by Almeida~\cite{almeida2023synchronization}
provides a user-space implementation of RA-TDMAs+ on Linux. Its architecture
separates a core scheduling module from a set of independently loaded
plug-in modules, allowing components to be added or replaced without
disrupting the core. The modules used in this work are the
topology-tracking module (\texttt{matrix.c}) and the Synchroniser.

\subsection{Core Scheduling Module}

\texttt{TDMA\_Core} manages medium access. Four threads divide its
responsibilities. The transmit thread (TX) is scheduled to wake at the
beginning of the node's slot and sleeps for the remainder of the frame; when
active, it dequeues packets, prepends a TDMA header, and transmits them via a
UDP socket over \texttt{wlan0}. The TDMA header carries the packet type, a
global sequence number, the transmission offset $p_k$ relative to the slot
start, the node ID, and the current slot boundaries. The receive thread (RX)
listens on the same UDP socket, strips incoming TDMA headers, records the
per-packet timing information needed for synchronisation, and returns payloads
to the application. The event-handler thread processes control events received
from plug-in modules over AF\_UNIX local sockets, such as updated slot limits
from the Synchroniser or membership changes from \texttt{matrix.c}. The
configuration thread manages round parameters and coordinates the scheduling
of the TX thread.

Applications access the framework through a TUN virtual network interface
(\texttt{tun0}). TUN presents itself to the operating system as a standard
Layer 3 (network-layer) network interface: IP packets sent by an application
to \texttt{tun0} are read by \texttt{TDMA\_Core} in user space, encapsulated
with the TDMA header, and queued for transmission during the node's slot.
On the receive side, stripped payloads are injected back into \texttt{tun0}
and delivered to the destination application as ordinary IP datagrams, making
the TDMA transport layer transparent to higher layers.

\subsection{Topology-Tracking Module}

The topology-tracking module (\texttt{matrix.c}) implements the connectivity
matrix mechanism described in Section~\ref{sec:ra-tdma}. Matrix state is held
in a packed structure:

\begin{lstlisting}[language=C,
    caption={Connectivity matrix structure (\texttt{matrix.c})},
    label={lst:matrix}]
typedef struct {
    uint8_t myId;
    uint8_t numberOfActiveNodes;
    uint8_t matrix[MNUM_DRONES][MNUM_DRONES];
    uint8_t idOfActiveNodes[MNUM_DRONES];
    double  creationTime[MNUM_DRONES];
    double  age[MNUM_DRONES];
} __attribute__((__packed__)) tdma_matrix_t;
\end{lstlisting}

At the start of each slot, stale rows (age exceeding three rounds) are
removed, the local row is updated with currently active links, and the
serialised matrix is broadcast via multicast. Incoming matrices are parsed
by \texttt{MATRIX\_parsePkt()}, which merges each row into the local copy
using the age field to resolve conflicts. Membership changes trigger an event
to \texttt{TDMA\_Core} so that the slot schedule can be reorganised. The
module also computes an MST from the current connectivity graph using Prim's
algorithm and writes the result to shared memory:

\begin{lstlisting}[language=C,
    caption={Spanning tree in shared memory},
    label={lst:spanning}]
typedef struct {
    pthread_mutex_t mut_spanningTree;
    uint8_t numberOfActiveNodes;
    uint8_t spanningTree[MNUM_DRONES][MNUM_DRONES];
    uint8_t idOfActiveNodes[MNUM_DRONES];
} spanningTreeSHM_t;
\end{lstlisting}

\subsection{Synchroniser Module}

The Synchroniser implements the slot-adjustment algorithm from
Equations~\ref{eq:delay}--\ref{eq:slot-start}. It wakes three milliseconds
before the end of each round, giving it enough time to compute and report
the shift $\Delta(r)$ before \texttt{TDMA\_Core} applies it at the round
boundary. The module reads the per-packet delays from shared memory, filters
them through the spanning tree to exclude cyclic paths, averages the filtered
delays by sender ID, computes $\Delta(r)$ bounded by 25\% of the current slot
duration, and sends the result to \texttt{TDMA\_Core} as an event on the
AF\_UNIX socket.

\section{Routing in Mobile Ad-hoc Networks}
\label{sec:routing}

\subsection{Routing Challenges}

Routing in a MANET must solve a problem that does not exist in static
networks: forwarding decisions that are valid now may become invalid at any
moment as nodes move and links change. A routing protocol for MANETs must
continuously monitor the topology, detect failures quickly, and propagate
updated forwarding information to all affected nodes, all without a central
coordinator and with minimal communication overhead.

The topology information required for routing can be maintained in two
fundamentally different ways. Proactive protocols keep an up-to-date routing
table at all times through periodic exchanges, making routes immediately
available but incurring continuous control overhead. Reactive protocols build
routes on demand, eliminating overhead during idle periods but introducing
discovery latency before the first packet of each flow can be forwarded.
Hybrid approaches combine elements of both. Each strategy involves different
trade-offs in latency, overhead, and scalability.

\subsection{Proactive Protocols}

\textbf{Destination-Sequenced Distance Vector (DSDV)} assigns a unique
sequence number to each routing table entry. Nodes periodically broadcast
their routing tables; when a node receives an update, it keeps the entry with
the higher sequence number, ensuring that newer information always overrides
stale entries and preventing count-to-infinity loops inherent in classical
distance-vector protocols. Updates can be sent as full dumps or as incremental
changes, reducing bandwidth usage during stable periods. The principal
limitation of DSDV is that periodic broadcasts consume resources even when
no topology changes have occurred, and the convergence time after a failure
depends on the broadcast interval.

\textbf{Optimised Link State Routing (OLSR)} is a proactive link-state
protocol in which each node selects a subset of its one-hop neighbours as
Multipoint Relays (MPRs). Control traffic is relayed only by MPRs, replacing
the full flooding of classical link-state protocols with a targeted subset
relay and substantially reducing overhead in dense networks. Nodes exchange
Hello messages to maintain neighbour lists and MPR selections; MPRs generate
Topology Control (TC) messages that describe their selector sets. Each node
accumulates TC messages, reconstructs the full network graph, and applies
Dijkstra's algorithm to compute the shortest-path routing table. OLSR is
well-suited to larger, denser networks where the overhead reduction from MPR
selection is significant.

\subsection{Reactive Protocols}

\textbf{Dynamic Source Routing (DSR)} discovers routes on demand. A source
without a cached route broadcasts a Route Request (RREQ) that accumulates
the list of nodes it traverses. The destination (or any intermediate node
with a valid cached route) replies with a Route Reply (RREP) listing the
complete path. Subsequent packets carry the full path in their headers, and
intermediate nodes simply read the next-hop field without maintaining routing
state. A Route Error (RERR) message notifies the source when a link on the
active path fails. Because routing information is embedded in packet headers
rather than stored in routing tables, DSR requires no periodic control
traffic, but it introduces discovery latency proportional to the number of
hops traversed and increases packet overhead with the embedded path.

\textbf{Ad-hoc On-demand Distance Vector (AODV)} uses the same RREQ/RREP/RERR
discovery mechanism as DSR but adopts per-hop next-hop routing: intermediate
nodes store the next hop toward the destination rather than the full path, and
packet headers carry no routing information. Sequence numbers borrowed from
DSDV ensure that only the freshest route information is accepted. Routes
expire if unused for longer than a configurable Active Route Timeout, keeping
the routing table free of stale entries. When a failure is detected, RERR
messages propagate upstream to notify affected sources, which may then
initiate new discoveries.

\subsection{Applicability to RA-TDMAs+}
\label{sec:routing-applicability}

The RA-TDMAs+ connectivity matrix, broadcast at every slot boundary,
provides every node with a fresh, consistent view of the full network
topology without any additional control traffic. This has direct implications
for the choice of routing approach.

Reactive discovery is redundant: the topology is already known, so there is
no information to be gained from flooding RREQ packets. Moreover, in a TDMA
network each hop of a flood must wait for the relevant node's transmission
slot, introducing latency of up to one frame per hop before a discovery
completes. For a three-hop discovery, the delay is at least three frames
(450\,ms at 150\,ms per frame), which is unacceptable for a real-time video
stream that must recover from a link failure within seconds.

Proactive protocols are the natural fit. OLSR's Hello messages duplicate the
neighbour-discovery function already served by the MATRIX beacon; the MPR
selection mechanism reduces flooding overhead but offers diminishing returns
in the small networks (three to ten nodes) typical of robotic applications.
DSDV's distance-vector computation can be performed directly on the
connectivity matrix without any additional broadcasts. However, sharing a
separate routing table alongside the MATRIX beacon increases the size of
each beacon packet, whereas computing routes locally from the matrix requires
no additional transmissions at all.

The conclusion is that a proactive routing algorithm that operates solely on
the connectivity matrix, recomputing routes each time the matrix is updated,
avoids all additional control traffic and adapts to topology changes within
one round of the MATRIX beacon. Table~\ref{tab:protocols} summarises the
key characteristics of the reviewed protocols in this context.

\subsection{Minimum Spanning Tree as Routing Basis}

A Minimum Spanning Tree (MST) of a weighted graph $G = (V, E, w)$ is a
cycle-free subgraph that connects all vertices and minimises the total edge
weight:

\begin{equation}
\mathrm{MST}(G) = \underset{T \subseteq E}{\mathrm{argmin}}
\sum_{(u,v) \in T} w(u,v) \quad \text{subject to } T \text{ spans } V
\label{eq:mst}
\end{equation}

When edge weights are defined as the cost of each link (for example, the
inverse of a link quality score), the MST selects the set of best available
links that still connect all nodes. Because the MST is a tree, there is a
unique path between any two nodes, which simplifies next-hop derivation:
for any destination, the next hop from a given node is the first step on the
unique tree path toward that destination.

Prim's algorithm~\cite{dijkstra1959note} constructs the MST incrementally,
starting from a root node and at each step adding the lowest-cost edge that
connects the growing tree to an unvisited node. The time complexity is
$O(N^2)$ for the dense adjacency matrix representation, which is negligible
for networks of fewer than ten nodes.

\section{Previous Routing Work in RA-TDMAs+}
\label{sec:related-work}

Morais~\cite{morais2024synchronization} implemented the first routing
mechanism for RA-TDMAs+ networks. Her approach operated at the data link
layer (Layer 2): forwarding decisions were implemented by modifying
destination MAC addresses at each relay hop, while IP headers remained
unchanged throughout the path. This made the relay transparent to
applications, which observed an apparently direct IP path to the
destination regardless of the number of relay hops.

Routes were computed from the connectivity matrix provided by the MATRIX
beacon using Prim's MST algorithm, which is the same strategy adopted in the
present work. Practical experiments on physical AlphaBot2-Pi robots
successfully demonstrated video streaming over a multi-hop path, establishing
the viability of MST-based proactive routing in this framework.

The Layer 2 forwarding strategy has limitations that become apparent in
practice. Standard IP diagnostic tools such as \texttt{traceroute} and
\texttt{ping} communicate exclusively through the IP layer and therefore
cannot observe MAC-level forwarding; the actual relay path is invisible to
these tools, complicating debugging and monitoring. Similarly, Linux
networking features that operate at the IP layer, including policy routing,
traffic shaping with \texttt{tc}, and firewall rules with \texttt{iptables},
cannot interact with a forwarding mechanism that operates below them. The
existing implementation also exhibited system-level instability during
operation, including runtime failures of undetermined origin. Finally, the
source code from that work was not made available; only the TDMA framework of
Almeida~\cite{almeida2023synchronization} could be used as a starting point.

These factors jointly motivated the development of a new routing system from
the ground up. The Layer 3 architecture adopted in this work installs routes
into the Linux kernel routing table via the Netlink interface and relies on
the kernel's own IP forwarding engine to relay transit packets. This
approach preserves full compatibility with standard IP tools, integrates
naturally with Linux networking subsystems, and benefits from decades of
production hardening in the kernel networking stack. The design and
implementation are described in Chapter~\ref{chap:implementation}.

\section{Summary}
\label{sec:background-summary}

This chapter established the background for the routing work described in the
remainder of this dissertation. The need for multi-hop routing arises from
the limited radio range of individual nodes in a MANET, combined with the
continuous topology changes caused by node mobility. RA-TDMAs+ addresses
the medium access and synchronisation problems through a clockless distributed
TDMA protocol that also distributes a continuously updated connectivity
matrix to all nodes. This matrix is the foundation on which routing can be
built without any additional control traffic. Among the routing approaches
reviewed, a proactive MST-based strategy operating directly on the
connectivity matrix was identified as the most natural fit for the
RA-TDMAs+ framework. The previous Layer 2 routing implementation by Morais
demonstrated the feasibility of MST routing in this context; the present work
extends that foundation with a Layer 3 architecture that offers better
observability, tighter integration with the Linux networking stack, and a
clean-slate implementation on top of the TDMA framework by Almeida.
