\chapter{Background and State of the Art}
\label{chap:background}

This chapter begins with a brief overview of the protocol stack that structures
modern network communication. It then introduces the core concepts of
wireless ad-hoc networking and Mobile Ad-hoc Networks. The following sections
describe the RA-TDMAs+ protocol and the TDMA implementation framework on
which this work was built. The chapter concludes with a review of established
routing protocols for MANETs and an analysis of their applicability to the
RA-TDMAs+ framework.

\section{Protocol Stack}
\label{sec:protocol-stack}

The protocol stack is a fundamental abstraction in network design, enabling
the structured and modular development of communication protocols. It
simplifies the network communication process into manageable layers, each
with distinct functions and responsibilities. Two primary models describe
layered protocol stacks: the Open Systems Interconnection (OSI) reference
model and the TCP/IP model.

The OSI model divides the stack into seven layers. The \textbf{Physical layer}
transmits raw bits over a physical medium, whether electrical signals over
copper, optical pulses over fibre, or radio waves over air. The \textbf{Data
Link layer} groups bits into frames, provides node-to-node transfer, and
handles error detection and correction at the link level; it is subdivided
into the Logical Link Control (LLC) sublayer for framing and the Media
Access Control (MAC) sublayer for access to the shared medium. The
\textbf{Network layer} processes packets, manages logical addressing, and
determines paths across multiple nodes and networks; the Internet Protocol
(IP) operates at this layer. The \textbf{Transport layer} ensures end-to-end
reliability and flow control, breaking large messages into segments when
necessary; TCP and UDP are the canonical examples. The \textbf{Session},
\textbf{Presentation}, and \textbf{Application} layers collectively manage
session lifecycle, data encoding and encryption, and the interface between
the network and user-facing software.

The TCP/IP model collapses the seven OSI layers into four: Link, Network,
Transport, and Application. The upper three OSI layers are subsumed into the
Application layer of TCP/IP and implemented there when needed.

This layered view is directly relevant to the routing work described in this
dissertation. The TDMA framework operates across the Physical and Data Link
layers. The routing mechanism developed here operates at the Network layer,
installing routes into the kernel's IP forwarding table so that transit packets
traverse multi-hop paths transparently from the perspective of Transport and
Application layers.

\section{Wireless Ad-hoc Networks}
\label{sec:manet}

\subsection{IEEE 802.11 (WiFi)}

IEEE 802.11, commonly known as WiFi, is a family of wireless local area
networking standards that defines protocols for wireless communication in
half-duplex mode. Because all nodes share the same radio medium, a Medium
Access Control (MAC) mechanism is required to coordinate transmissions and
avoid collisions.

The MAC protocol used by standard WiFi is Carrier Sense Multiple Access with
Collision Avoidance (CSMA/CA). Before transmitting, a node listens to the
channel; if the channel is idle, the node waits for a random backoff interval
and then transmits. If the channel is busy, the node defers and tries again
after the backoff expires. CSMA/CA reduces the probability of collisions but
cannot eliminate them entirely: when two nodes select the same backoff, they
transmit simultaneously and their packets collide at the receiver.

CSMA/CA also suffers from the hidden terminal problem. Two nodes that are
each within range of a common third node but out of range of each other
cannot detect each other's transmissions. They may therefore transmit
simultaneously, causing a collision at the common node that neither sender
detects. Under high network load, these mechanisms can lead to significant
delays and communication failures.

The RA-TDMAs+ protocol overlays CSMA/CA with a TDMA schedule. Within the
team, each node transmits only in its assigned time slot, making intra-team
collisions impossible by construction. CSMA/CA remains active at the hardware
level to handle external interference from nodes outside the team.

\subsection{Ad-hoc Networks}

Ad-hoc networks are decentralised wireless networks that operate without
pre-existing infrastructure such as routers or access points. Individual
nodes communicate directly with each other or through intermediate nodes
that act as relays, so each node functions simultaneously as host and
router. Routing decisions are made dynamically based on the current network
topology, without any central authority.

The absence of fixed infrastructure makes ad-hoc networks inherently
scalable and robust: nodes can be added or removed without reconfiguring any
centralised component, and the network can reroute around node failures.
This adaptability is valuable for teams of mobile robots that must
communicate reliably as their relative positions change.

A widely used approach to synchronisation in networks is a global clock
obtained from an external source such as GPS or NTP. However, external
references are often unavailable in ad-hoc scenarios, and the overhead of
transmitting timing information at regular intervals can interfere with
data traffic~\cite{oliveira2018clockless}. The mobile and ad-hoc
characteristics of the network also cause poor performance of standard
synchronisation protocols, primarily due to asymmetric and unstable links
and variable forwarding delays~\cite{sousa2012ra}. A relative
synchronisation protocol, in which nodes adjust their timing based on
observations of each other's transmissions without needing a global
reference, is therefore preferable. RA-TDMAs+, described in
Section~\ref{sec:ra-tdma}, is built on this principle.

\subsection{Mobile Ad-hoc Networks}

A Mobile Ad-hoc Network (MANET) is a self-configuring wireless network
composed of nodes that move dynamically~\cite{conti2014mobile}. Each node
acts simultaneously as a communication endpoint and as a router, relaying
packets on behalf of other nodes. Because the transmission range of any
single node is limited, multi-hop paths through intermediate relay nodes
are necessary to connect node pairs that are not within direct radio range.
This decentralised multi-hop paradigm eliminates dependence on infrastructure
and avoids single points of failure.

The defining characteristic of MANETs is their highly dynamic topology.
Nodes move independently in any direction, causing links to appear and
disappear on timescales from milliseconds to seconds. Routing protocols must
detect topology changes quickly and update forwarding paths before the
disruption becomes perceptible to the application. Resource constraints
add further difficulty: battery-powered nodes have limited energy budgets,
so routing protocols must minimise control overhead to extend operational
lifetime.

Applications of MANETs include military tactical communications, emergency
response coordination in disaster areas where infrastructure has been
destroyed, industrial inspection with mobile robots, and surveillance
operations in environments without fixed networking equipment. The scenario
addressed in this dissertation, a mobile robot streaming video to a base
station through an intermediate relay, is a concrete instance of this last
category.

\section{RA-TDMAs+ Protocol}
\label{sec:ra-tdma}

\subsection{Overview}

RA-TDMAs+~\cite{oliveira2018clockless} is a TDMA protocol that achieves
clockless relative synchronisation in dynamic ad-hoc mesh networks. It
combines the synchronisation algorithm of RA-TDMAs~\cite{sousa2012ra} with
the topology-tracking mechanism of RA-TDMA+, producing a protocol that
simultaneously provides collision-free medium access, distributed
synchronisation without a global clock, and a continuously updated view of
the network topology available to all nodes.

\subsection{TDMA}

Time Division Multiple Access (TDMA) is a medium access protocol that divides
time into a repeating sequence of frames. Each frame is subdivided into $N$
slots, one per node. A node transmits data only during its assigned slot, so
at most one node transmits at any instant and collisions are impossible by
construction.

Let $T_{slot}$ denote the duration of each slot and $N$ the number of active
nodes. The frame duration is:

\begin{equation}
T_{frame} = N \times T_{slot}
\label{eq:frame-duration}
\end{equation}

A guard interval $T_{guard}$ is typically inserted between consecutive slots
to absorb residual clock drift and propagation delay, ensuring that
transmission from one node ends before the next node begins. The maximum
end-to-end latency for a single packet is bounded by one full frame, making
TDMA suitable for real-time applications with known timing requirements.

\subsection{RA-TDMA}

For TDMA to work effectively in a wireless network, all participating nodes
must share a consistent perception of where slot boundaries lie. In
infrastructure-based networks this is achieved by distributing a global clock
from a central station. In ad-hoc networks no such station is available, and
relative synchronisation is needed instead: nodes adjust their own slot
boundaries based on the timing of transmissions they observe from their
neighbours, without requiring any common external reference.

RA-TDMA~\cite{sousa2012ra} formalises this approach. Each node transmits a
packet at the beginning of its designated slot. A receiving node $j$ observes
the actual arrival time of each packet $k$ from node $i$ and compares it
to the expected arrival time derived from the known slot structure.

\subsection{RA-TDMAs Synchronisation Method}
\label{sec:sync-method}

RA-TDMAs~\cite{sousa2012ra} extended RA-TDMA to support video streaming
over relay networks with a line topology. Its synchronisation mechanism is
the basis of RA-TDMAs+.

The delay of received packet $k$ is computed as:

\begin{equation}
\delta_k = (rx_k - \hat{rx}_k + T/2)_T - T/2
\label{eq:sync-delay}
\end{equation}

where $rx_k$ is the measured reception time and $\hat{rx}_k$ is the expected
reception time, both expressed in the receiver's round-time coordinate. The
modular arithmetic keeps $\delta_k$ in the range $(-T/2, T/2)$.

The expected reception time is derived from the slot structure. Assuming
that node $j$ is synchronised with its neighbour node $i$, node $j$ knows
its own slot start $B^{(j)}$ and can estimate the start of node $i$'s slot
as:

\begin{equation}
\hat{B}^{(i)}_k = (B^{(j)} - (j - i)s + T)_T, \quad j, i \in [1, n],
\quad s = T/n
\label{eq:expected-start}
\end{equation}

where $s$ is the slot duration and $n$ is the number of nodes. Each packet
carries the transmission offset $p_k$ from the start of the sender's slot,
so the expected arrival is:

\begin{equation}
\hat{rx}_k = (\hat{B}^{(i)} + p_k)_T
\label{eq:expected-arrival}
\end{equation}

Before the beginning of each slot, the delays accumulated during the previous
round are passed to a delay function $f$ that selects a representative delay
value (minimum, maximum, or median). The resulting slot shift is bounded to
prevent excessive correction:

\begin{equation}
\Delta(r) = \min\!\bigl(\max\bigl(f(\delta_1, \delta_2, \ldots), 0\bigr),\,
\Delta_{max}\bigr)
\label{eq:shift}
\end{equation}

where $\Delta_{max}$ is a configurable maximum shift, set to at most 25\% of
the slot duration. The slot start for the next round is then:

\begin{equation}
B^{(j)}(r) = B^{(j)}(r-1) + \Delta(r)
\label{eq:slot-update}
\end{equation}

Slots can only be delayed, never advanced, and the process converges when
all nodes have adjusted their timing so that the observed delay is zero.

\subsection{RA-TDMA+: Topology Tracking}

RA-TDMA+~\cite{oliveira2018clockless} extended the RA-TDMA protocol to
dynamic mesh networks by adding a topology-tracking mechanism. Each node
maintains a connectivity matrix $M$ where entry $M_{jk} = 1$ indicates
that node $j$ is currently receiving packets from node $k$, and
$M_{jk} = 0$ indicates no active link.

At the beginning of each slot, a node broadcasts its current matrix row
along with the aggregated matrix received from other nodes. Receiving nodes
update their local copy of the matrix using the most recent information
from each row, identified by an age field. This flooding-with-aggregation
process ensures that within a bounded number of rounds every node obtains a
consistent view of the full network topology, even when the network is not
fully connected.

Membership changes are handled automatically. When a new node joins, its
matrix row appears in the next broadcast and all nodes add it to their
local copies, extending the round by one slot. When a node departs or loses
connectivity, its row ages past a threshold of three consecutive rounds
without fresh information, and all nodes remove it from their copies,
contracting the round accordingly.

\subsection{RA-TDMAs+: Combined Protocol}

RA-TDMAs+ unifies the synchronisation mechanism of RA-TDMAs with the
topology-tracking and membership-management mechanisms of RA-TDMA+. The
result is a protocol that achieves clockless relative synchronisation on
fully dynamic mesh networks, distributes a continuously updated connectivity
matrix to every node, and adapts the round structure automatically as
nodes join or depart.

The synchronisation mechanism uses the connectivity matrix to filter delays:
only delays observed on links that appear in the spanning tree of the
connectivity graph are used to compute slot shifts, avoiding feedback loops
that would arise if delays were combined across topological cycles.

\section{TDMA Implementation Framework}
\label{sec:framework}

The experimental TDMA framework developed by
Almeida~\cite{almeida2023synchronization} implements RA-TDMAs+ in user space
on Linux and provides a modular, event-driven architecture. The framework is
composed of two parts: a core TDMA module (\texttt{TDMA\_Core}) that handles
the timing and communication logic of a TDMA round, and a set of optional
plug-in modules that can be added or removed without disrupting the core.
The modules relevant to this work are the Topology-Tracking module
(\texttt{matrix.c}) and the Synchroniser.

\subsection{TDMA\_Core}

\texttt{TDMA\_Core} controls access to the shared wireless medium. It is
structured around four concurrent threads.

The \textbf{TX thread} is active only during the node's assigned slot and
remains idle for the rest of the frame. During its active period it dequeues
packets from the TX queue, prepends a TDMA header, and dispatches them via a
UDP socket over the physical Wi-Fi interface (\texttt{wlan0}). The TDMA
header carries the packet type, a global sequence number, the relative
transmission timestamp (expressed in units of the current round time), the
node ID, and the current slot boundaries. The header allows receivers to
compute the synchronisation delay $\delta_k$ from Equation~\ref{eq:sync-delay}.

The \textbf{RX thread} receives packets from \texttt{wlan0}, strips the TDMA
header, records the per-packet delay for the synchroniser, and delivers the
payload to the application via the TUN virtual interface (\texttt{tun0}).

The \textbf{Event Handler thread} processes control events sent by plug-in
modules over AF\_UNIX local sockets, such as slot limit updates from the
synchroniser or topology changes from \texttt{matrix.c}.

The \textbf{Config thread} manages the overall round configuration and
controls the TX thread's wake-up scheduling.

Applications interface with the framework through the \texttt{tun0} virtual
interface, which presents itself as a standard network device. IP packets
sent by an application to \texttt{tun0} are intercepted by \texttt{TDMA\_Core}
in user space, encapsulated with the TDMA header, and transmitted during the
node's slot. On the receive side, the payload returned to \texttt{tun0} is
delivered to the destination application as a normal IP datagram, making the
TDMA transport layer transparent to the application.

\subsection{Topology-Tracking Module}

The Topology-Tracking module, implemented in \texttt{matrix.c}, maintains the
connectivity matrix and distributes it to the network. The matrix information
is stored in a packed C structure:

\begin{lstlisting}[language=C, caption={Variables used to store the matrix (\texttt{matrix.c})},
                   label={lst:matrix}]
typedef struct {
    uint8_t myId;
    uint8_t numberOfActiveNodes;
    uint8_t matrix[MNUM_DRONES][MNUM_DRONES];
    uint8_t idOfActiveNodes[MNUM_DRONES];
    double  creationTime[MNUM_DRONES];
    double  age[MNUM_DRONES];
} __attribute__((__packed__)) tdma_matrix_t;
\end{lstlisting}

At the beginning of each slot, the module removes rows whose age exceeds a
threshold of three consecutive rounds (indicating a departed node), updates
the local row with the links currently active, and broadcasts the serialised
matrix. Receiving nodes invoke \texttt{MATRIX\_parsePkt()} to deserialise the
packet and merge the new information into their local copy, keeping the
freshest entry for each row. When the set of active nodes or the slot
assignment changes, the module notifies \texttt{TDMA\_Core} via an event on
the AF\_UNIX socket.

After updating the matrix, the module computes a Minimum Spanning Tree (MST)
from the connectivity graph using Prim's algorithm and writes the result to
shared memory:

\begin{lstlisting}[language=C, caption={Spanning tree shared memory structure},
                   label={lst:spanning-tree}]
typedef struct {
    pthread_mutex_t mut_spanningTree;
    uint8_t numberOfActiveNodes;
    uint8_t spanningTree[MNUM_DRONES][MNUM_DRONES];
    uint8_t idOfActiveNodes[MNUM_DRONES];
} spanningTreeSHM_t;
\end{lstlisting}

The spanning tree is used by the Synchroniser to filter delays and by the
routing layer to derive forwarding paths.

\subsection{Synchroniser Module}

The Synchroniser implements the RA-TDMAs+ clock-adjustment algorithm described
in Section~\ref{sec:sync-method}. It wakes up three milliseconds before the
end of each TDMA round to allow enough time to compute and apply the slot
shift before the next round begins.

The module reads the per-packet delay values accumulated by \texttt{TDMA\_Core}
from shared memory and filters them through the MST: only delays from links
that appear in the spanning tree are used, avoiding synchronisation loops
caused by topological cycles. The filtered delays are grouped by sender ID, the
median delay per sender is computed, and the shift $\Delta(r)$ is derived from
Equation~\ref{eq:shift} with $\Delta_{max}$ set to 25\% of the current slot
duration. The computed shift is sent to \texttt{TDMA\_Core} as an event, which
applies it before the next slot begins.

\section{Routing Protocols for MANETs}
\label{sec:routing}

The highly dynamic topology of a MANET requires routing protocols that can
adapt quickly to topology changes without centralised coordination. This
section reviews established MANET routing protocols and analyses their
applicability to the RA-TDMAs+ framework.

Topology-based routing protocols are typically classified into three
categories. \textbf{Proactive} (table-driven) protocols maintain routes to
all known destinations at all times, updating them through periodic exchanges.
Routes are immediately available when needed, at the cost of continuous
control traffic. \textbf{Reactive} (on-demand) protocols discover routes only
when traffic must be forwarded, eliminating periodic overhead but introducing
latency before the first packet of each flow. \textbf{Hybrid} protocols
combine elements of both to balance overhead and discovery latency.

\subsection{Destination-Sequenced Distance Vector (DSDV)}

DSDV is a proactive protocol derived from the Bellman-Ford distance vector
algorithm. Each node maintains a routing table listing every known
destination, the number of hops to reach it, and a monotonically increasing
sequence number that reflects the freshness of that entry. Nodes periodically
broadcast their tables; on receiving an update, a node compares sequence
numbers and keeps the most recent entry for each destination.

Updates may be distributed as full dumps (the entire routing table) or as
incremental carries (only entries that changed since the last dump). The
sequence number mechanism prevents routing loops and solves the
count-to-infinity problem that affects classical distance vector protocols.
However, periodic updates consume bandwidth and battery power even when the
topology is stable, and the convergence time after a topology change depends
on the broadcast period, making DSDV less suitable for highly dynamic
networks.

\subsection{Dynamic Source Routing (DSR)}

DSR is a reactive, source-routing protocol. The complete route is embedded
in each packet header; intermediate nodes read the next hop from the header
and do not need to maintain routing state for destinations they are
forwarding to. Route discovery is initiated on demand: the source broadcasts
a Route Request (RREQ) that accumulates the path it traverses, and the
destination or any intermediate node with a cached route responds with a
Route Reply (RREP) containing the full path.

Route maintenance uses Route Error (RERR) messages: when a node detects a
link failure on an active route, it sends a RERR to the source, which
removes the cached route and initiates a new discovery. The absence of
per-hop routing state reduces memory usage but increases packet overhead and
makes route freshness dependent on the source node's cached topology view.

\subsection{Ad-hoc On-demand Distance Vector (AODV)}

AODV is a reactive protocol that combines the on-demand route discovery of
DSR with the distance vector (next-hop) forwarding of DSDV. Route discovery
uses the same RREQ/RREP mechanism as DSR, but intermediate nodes store the
next hop toward the destination rather than the full path, so packets carry
no route information in their headers. Monotonically increasing sequence
numbers prevent stale route reuse.

Routes have an Active Route Timeout: unused entries are purged after a
configurable period. When a link or node fails, AODV issues a Route Error
(RERR) message that propagates upstream along all active routes through the
failed link, notifying affected sources, which then initiate new discoveries.
The per-hop storage model allows intermediate nodes that detect a topology
change to reroute packets using a locally updated view, reducing the number
of new discoveries needed compared to DSR.

\subsection{Optimised Link State Routing (OLSR)}

OLSR is a proactive link-state protocol optimised for dense ad-hoc networks.
Each node selects a subset of its one-hop neighbours as Multipoint Relays
(MPRs). Only MPRs retransmit control traffic, replacing network-wide flooding
with a targeted subset relay and substantially reducing control overhead
compared to classical link-state flooding.

Nodes exchange Hello messages to discover neighbours and advertise MPR
selections. MPRs generate Topology Control (TC) messages describing link-state
information for their MPR selectors. Each node accumulates TC messages,
constructs a full topology map, and applies Dijkstra's algorithm to compute
the routing table. The routing table is recalculated whenever a neighbour
change or link expiry is detected.

\subsection{Analysis for RA-TDMAs+}
\label{sec:routing-analysis}

The RA-TDMAs+ framework already distributes topology information via the
MATRIX beacon at the beginning of each TDMA slot. This periodic exchange
provides every node with a fresh, consistent view of the full network
topology without any additional control traffic. The implications for the
choice of routing protocol are substantial.

Reactive protocols (DSR, AODV) initiate route discovery by flooding the
network with RREQs. In a TDMA network, each hop in the flood must wait for
the transmitting node's designated slot before forwarding the RREQ. A
discovery across three hops therefore requires at least three consecutive
slots, introducing multi-frame latency before the first data packet can be
forwarded. Since the connectivity matrix already provides a complete topology
view, route discovery is not necessary: routes can be computed locally from
the matrix without any additional message exchange. On-demand discovery in
this context adds delay without providing any information that is not already
available.

Proactive protocols (DSDV, OLSR) maintain routes continuously. In DSDV,
routing tables would have to be broadcast separately in addition to the
MATRIX beacon, increasing overhead. OLSR's Hello messages perform the same
neighbour-discovery function already handled by the MATRIX beacon; MPR
selection reduces control floods, but the benefit diminishes in small
networks (the three- to ten-node teams typical of robotic applications)
where all nodes can hear each other or are at most two hops apart.

The conclusion is that a proactive link-state approach that operates directly
on the connectivity matrix, without any separate topology discovery, is the
most efficient and natural fit for the RA-TDMAs+ framework. Routing
decisions are updated each time a new MATRIX beacon is received, using the
up-to-date topology graph that the beacon provides.

\subsection{Minimum Spanning Tree Routing}

A Minimum Spanning Tree (MST) of a weighted graph $G = (V, E, w)$ is the
subgraph $T \subseteq E$ that connects all vertices with minimum total edge
weight and contains no cycles:

\begin{equation}
\mathrm{MST}(G) = \underset{T \subseteq E}{\mathrm{argmin}}
\sum_{(u,v) \in T} w(u,v)
\quad \text{subject to } T \text{ spans } V
\label{eq:mst}
\end{equation}

When link weights represent link cost (the inverse of link quality), the MST
naturally selects the set of highest-quality links that still connect all
nodes. A node derives its routing table from the MST by identifying, for each
destination, the first hop on the unique tree path from itself to that
destination. Prim's algorithm~\cite{dijkstra1959note} constructs the MST
greedily, starting from a root node and repeatedly adding the minimum-weight
edge connecting the growing tree to an unvisited node. For $N$ nodes the time
complexity is $O(N^2)$, which is negligible for the small teams considered
here.

The MST was adopted by Morais~\cite{morais2024synchronization} as the routing
basis for her Layer 2 implementation and is retained in the present work for
consistency and comparability.

\section{Related Work}
\label{sec:related-work}

Morais~\cite{morais2024synchronization} presented the first routing mechanism
for RA-TDMAs+ networks. Her work operated at the data link layer (Layer 2)
through ARP table manipulation on AlphaBot2-Pi robotic platforms. Routes
were computed using Prim's MST algorithm applied to the connectivity matrix
distributed by the MATRIX beacon, and forwarding was achieved by rewriting
destination MAC addresses at each relay hop while leaving IP headers
unchanged throughout the path, providing transparency to higher-layer
protocols. Practical experiments on physical robots demonstrated real-time
video streaming across a multi-hop topology, establishing the feasibility of
multi-hop communication in this context and validating the MST routing
strategy.

The Layer 2 approach has inherent observability limitations: standard network
diagnostic tools such as \texttt{traceroute} and \texttt{ping} operate at the
network layer and cannot observe MAC-level forwarding decisions, making
troubleshooting complex. Integration with Linux network management features
such as \texttt{ip route} and \texttt{iptables} is also constrained when
forwarding occurs below the IP layer. The implementation exhibited system-level
instability during operation, including runtime failures whose precise cause
was not identified. Furthermore, the source code from that work was not
available for inspection or reuse; only the TDMA framework of
Almeida~\cite{almeida2023synchronization} was accessible.

The present dissertation addresses the routing problem through a Layer 3
architecture that integrates with the Linux kernel routing subsystem.
Routes are installed into the kernel routing table via the Netlink
interface, derived from an MST computed over a weighted link quality graph
built from TDMA beacon reception statistics. A dual routing table
architecture separates locally originated traffic from transit traffic,
allowing the kernel's native IP forwarding engine to relay packets without
any user-space intervention. The design and implementation of this system
are described in Chapter~\ref{chap:implementation}.

\section{Summary}
\label{sec:background-summary}

This chapter provided the theoretical and practical background necessary to
understand the routing system developed in this work. It covered the protocol
stack layers that frame the design space, the properties of MANETs that make
routing challenging, and the RA-TDMAs+ protocol that provides the medium
access and topology dissemination substrate. The TDMA implementation framework
of Almeida, on which the present work was built, was described in detail. The
review of MANET routing protocols showed that a proactive, MST-based approach
operating directly on the connectivity matrix provided by RA-TDMAs+ is the
most natural and efficient choice for this context. The previous Layer 2
routing work by Morais established the feasibility of multi-hop communication
and the effectiveness of the MST routing strategy; the present work builds on
that foundation with a Layer 3 architecture that addresses the observability
and stability limitations of the earlier approach.
