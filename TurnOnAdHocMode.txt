NOTA: O meshnode configura o IP automaticamente ao arrancar.
      Apenas precisa de colocar a interface em modo ad-hoc.
      Limpa o iptables antes de arrancar para evitar regras duplicadas.

PC (no 3 — IP sera 172.20.10.3):
  sudo systemctl stop NetworkManager
  sudo systemctl stop wpa_supplicant
  sudo ip link set wlp5s0 down
  sudo iwconfig wlp5s0 mode ad-hoc
  sudo iwconfig wlp5s0 essid manet-mesh
  sudo iwconfig wlp5s0 channel 6
  sudo ip link set wlp5s0 up
  # Limpar iptables duplicados (importante!)
  sudo iptables -t mangle -F
  for i in 1 2 3 4 5; do sudo ip rule del fwmark 1 table 100 2>/dev/null; done
  sudo ip route flush table 100

Raspberry AlphaBot (no 1 — IP sera 172.20.10.1):

  sudo iwconfig wlan0 mode ad-hoc
  sudo iwconfig wlan0 essid manet-mesh
  sudo iwconfig wlan0 channel 6

METODO ip_forward (Miguel) — TCP:
  PC — primeiro (fica em listen):
    ffplay -fflags nobuffer+discardcorrupt \
        -flags low_delay -framedrop -sync ext \
        -probesize 2048 -analyzeduration 500000 \
        -i "tcp://0.0.0.0:5000?listen=1"

  Raspberry — depois:
    rpicam-vid -t 0 --width 640 --height 480 --framerate 15 \
        --codec yuv420 -o - | \
    ffmpeg -fflags nobuffer \
        -f rawvideo -pix_fmt yuv420p -s 640x480 -r 15 -i - \
        -c:v libx264 -preset ultrafast -tune zerolatency \
        -g 1 -b:v 500000 \
        -f mpegts tcp://10.0.0.3:5000

METODO ARP trick (Ana) — UDP:
  PC:
    ffplay -fflags nobuffer+discardcorrupt \
        -flags low_delay -framedrop -sync ext \
        -probesize 2048 -analyzeduration 500000 \
        -i udp://0.0.0.0:5000

  Raspberry:
    rpicam-vid -t 0 --width 640 --height 480 --framerate 15 \
        --codec yuv420 -o - | \
    ffmpeg -fflags nobuffer \
        -f rawvideo -pix_fmt yuv420p -s 640x480 -r 15 -i - \
        -c:v libx264 -preset ultrafast -tune zerolatency \
        -g 1 -b:v 500000 \
        -f mpegts "udp://10.0.0.3:5000?pkt_size=1316"

5. TESTAR RELAY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Bloquear link 1 <-> 3 (em ambos os nos):
  No PC:           sudo iptables -I OUTPUT -d 172.20.10.1 -j DROP
                   sudo iptables -I INPUT  -s 172.20.10.1 -j DROP
  Na Raspberry 1:  sudo iptables -I OUTPUT -d 172.20.10.3 -j DROP
                   sudo iptables -I INPUT  -s 172.20.10.3 -j DROP

Remover bloqueio (em ambos):
  sudo iptables -F

O que deve acontecer com ip_forward + TCP:
  - ffmpeg fecha socket TCP
  - ffplay fica em listen
  - Routing recalcula via no 2
  - ffmpeg reconecta via nova rota
  - Stream recomeça limpo sem lag

O que deve acontecer com ARP trick + UDP:
  - Routing recalcula via no 2
  - Stream continua com possivel packet loss temporario
