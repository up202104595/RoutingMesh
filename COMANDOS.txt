--- 7a. POR IP (o natural no Layer 3: cada salto e identificado pelo IP) ---
# [N1]  (terminal do Pi)
sudo iptables -I INPUT -s 172.20.10.3 -j DROP

# [PC]  (janela "controlo")
sudo iptables -I INPUT -s 172.20.10.1 -j DROP

--- 7b. POR MAC (alternativa; corta tudo o que a trama traz daquele no) ---
# [N1]
sudo iptables -I INPUT -m mac --mac-source f0:9e:4a:a2:20:38 -j DROP

# [PC]
sudo iptables -I INPUT -m mac --mac-source d8:3a:dd:33:f3:be -j DROP

# Usa 7a OU 7b, nao os dois. Aplica SEMPRE nos dois lados (N1 e PC), um logo

11. PORQUE ESTE BLOQUEIO E NOS DOIS LADOS
-------------------------------------------------------------------------
- Simula a falha da ligacao direta N1-N3 por software (com tres nos nao da
  para os afastar quando se quer). Para a rede e igual a o radio ter caido:
  deixa de receber os beacons desse vizinho, ao fim de 2 s a ligacao sai da
  matriz de topologia, a arvore e recalculada e o unico caminho passa a ser
  pelo N2.
- Nos dois lados, porque a topologia mantem uma aresta se UM dos sentidos
  estiver confirmado (so lhe tira 20 pontos). Com um lado so, a ligacao
  pode ficar na arvore e nao ha desvio.
- Cadeia INPUT: so descarta o que o no RECEBE do outro.
- Por IP no Layer 3: cada salto e uma ligacao entre vizinhos enderecada ao
  IP do vizinho; o que passa pelo relay vem com o IP do relay (ou com IPs do
  overlay 10.0.0.x), por isso o filtro corta so a ligacao direta.
